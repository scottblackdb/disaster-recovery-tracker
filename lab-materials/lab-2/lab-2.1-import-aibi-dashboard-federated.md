# Lab 2 (Federated): Import the FEMA Claims AI/BI Dashboard

**Goal:** Import a pre-built **Databricks AI/BI dashboard** into your workspace so you can analyze the claims data that the Disaster Recovery Tracker app is writing into Lakebase — queried **live** through Unity Catalog via **Lakehouse Federation**, with no sync step in between.

**Dashboard file:** [`./aibi_dashboard/fema_claims_overview_federated.lvdash.json`](./aibi_dashboard/fema_claims_overview_federated.lvdash.json)

> **This is the federated version of Lab 2.** If your instructor set up the CDC/sync approach instead, follow [`lab-2.1-import-aibi-dashboard.md`](./lab-2.1-import-aibi-dashboard.md) and import `fema_claims_overview.lvdash.json` instead — same visuals, but that file queries `fema.silver.*` (the synced tables) rather than the federated catalog.

---

## Before you start

- Your instructor has already registered the Lakebase database as a Unity Catalog catalog (`lab-2-instructor-federate-lakebase.md`). You do **not** need to set this up yourself.
- You should have completed **Lab 1** and submitted at least one claim through the app so there is data to look at.
- You will need access to a SQL warehouse with **serverless compute enabled** (shown as **Serverless** in the warehouse picker). Federated Lakebase catalogs can't be queried by a non-serverless warehouse and will return a permission error.

---

## Part A — Confirm you can see the federated catalog

1. In the Databricks workspace left nav, open **Catalog Explorer**.
2. Find the **`fema_lakebase`** catalog your instructor registered.
3. Expand it → `public` and confirm you can see:
   - `claims`
   - `fema_categories`
   - `documents`
   - `claim_status_history`

If you don't see the catalog or get a permission error, ask your instructor to confirm you've been granted `USE CATALOG` / `SELECT`.

---

## Part B — Download the dashboard file

1. Open the workshop repository in your browser:
   [https://github.com/scottblackdb/disaster-recovery-tracker](https://github.com/scottblackdb/disaster-recovery-tracker)
2. Navigate to `lab-materials/lab-2/aibi_dashboard/`.
3. Open `fema_claims_overview_federated.lvdash.json` and click **Download raw file** (or right-click **Save As…**) to save it locally.

> This file is identical to `fema_claims_overview.lvdash.json` (used by the CDC/sync lab) except every dataset query points at `fema_lakebase.public.*` instead of `fema.silver.*`. There's no SCD Type 2 filtering logic to strip out, either — the federated tables already show current state.

---

## Part C — Import the dashboard into the workspace

1. In the Databricks workspace left nav, click **Workspace**.
2. Navigate to your **Home** folder (or any folder you have write access to).
3. Click the **kebab menu (⋮)** at the top right of the folder view, then choose **Import**.
4. In the **Import** dialog:
   - **Import from:** **File**
   - Drag in or browse to the `fema_claims_overview_federated.lvdash.json` you downloaded.
5. Click **Import**.
6. When the import completes, click the new **`fema_claims_overview_federated`** dashboard to open it.

---

## Part D — Attach a SQL warehouse and run the dashboard

1. With the dashboard open, look at the top-right corner for the **warehouse selector**.
2. Pick a **Serverless** SQL warehouse — this is required for federated Lakebase catalogs.
3. The dashboard will run all of its queries against the live tables in `fema_lakebase.public.*` and render the visuals.

You should see tiles such as:

| Tile | What it shows |
|------|----------------|
| Total claims | Overall claim count from `claims`. |
| Claims by FEMA category | `claims` joined to `fema_categories`. |
| Claims over time | Submissions trended by date. |
| Documents per claim | Counts from `documents`. |
| Status changes | Activity from `claim_status_history`. |
| Total Claims: Actual vs AI Forecast | Historical claim counts plus a 30-day forecast generated by `ai_forecast`. |
| Claim Amounts: Actual vs AI Forecast | Historical estimated cost plus a 30-day forecast generated by `ai_forecast`. |

---

## Part E — Publish and explore

1. Click **Publish** in the top right of the dashboard so others (and you, in view mode) can use it.
2. Try the following to get a feel for AI/BI:
   - Click any visual to **cross-filter** the rest of the dashboard.
   - Use the **Genie** / **Ask a question** entry point (top of the dashboard) to ask a natural-language question such as *"How many claims were submitted this week?"* or *"Which county has the most claims?"*.
   - Click **Edit** to see the SQL behind any tile — every visual is backed by a query against `fema_lakebase.public.*`.

---

## Part F — Watch live data flow end-to-end, with zero lag

1. Leave the dashboard open in one browser tab.
2. In another tab, open the Disaster Recovery Tracker app and submit a new claim (you can reuse the steps from **Lab 1.1**).
3. Click the **Refresh** button at the top of the dashboard — there's no sync delay to wait for, since the dashboard queries Postgres directly through Unity Catalog.
4. The new claim should appear immediately in the totals and trend tiles.

This is the full loop: the app writes to **Lakebase (OLTP)**, and the **AI/BI dashboard** queries that same Lakebase database **directly**, through a federated Unity Catalog catalog — no replication, no history table, no lag.

## Congratulations — you've imported and used an AI/BI dashboard backed live by Lakehouse Federation!

## Need help?

- **`TABLE_OR_VIEW_NOT_FOUND` errors on the tiles:** The dashboard queries `fema_lakebase.public.*`. If your instructor registered the federated catalog under a different name, click **Edit** → **Data** tab and change `fema_lakebase` to their catalog name in each dataset query. Otherwise, the instructor's registration step may not be complete — let them know.
- **Permission error when the dashboard runs a query:** Federated Lakebase catalogs require a warehouse with **serverless compute enabled**. Check the warehouse selector in the top right.
- **Tiles stuck on "Running":** Make sure a Serverless SQL warehouse is selected and in the **Running** state.
- **You don't see your new claim:** Click the dashboard's **Refresh** button — this should be near-instant since there's no sync to wait on. If it's still missing, confirm your claim actually committed in the app (check Lab 1's confirmation step).
- **AI Forecast tiles show an error:** `ai_forecast` needs at least ~10 days of historical claims to fit a model. If the workshop catalog is brand new, submit more claims (or wait for more days of data) and refresh the dashboard.
